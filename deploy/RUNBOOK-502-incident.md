# RUNBOOK: Debugging Cloudflare Tunnel 502 Host Errors

## Incident Description
The browser displays a `502 Bad Gateway — Host Error` from Cloudflare, despite the `cloudflared` agent reporting as healthy in the Zero Trust dashboard.

## Root Cause Analysis
A 502 Host Error generated by Cloudflare means the edge tunnel is successfully reaching the `cloudflared` container, but the internal request from `cloudflared` to the origin (`soc-nginx-proxy`) is failing.

This is almost exclusively caused by one of three things:
1. **TCP Keepalive Race Condition (Most Common)**
   - **Cause:** Cloudflared holds idle connections open for 90 seconds. If Nginx's `keepalive_timeout` is shorter (default is 65s), Nginx will quietly close the socket. If a new request arrives at 70s, Cloudflare tries to use the dead socket, resulting in a TCP RST and a 502 error.
   - **Fix:** Ensure `nginx.conf` has `keepalive_timeout 100s;` so Cloudflare always drops the connection first.

2. **IPv6 Docker DNS Drops**
   - **Cause:** Docker's internal DNS resolver occasionally drops IPv6 resolution requests, causing micro-timeouts inside `cloudflared`.
   - **Fix:** Force `cloudflared` to use IPv4 only by passing `TUNNEL_EDGE_BIND_ADDRESS=0.0.0.0` in `docker-compose.yml`.

3. **Nginx Startup Race Condition**
   - **Cause:** Cloudflared boots faster than Nginx, begins routing traffic to a dead port, and marks the origin offline.
   - **Fix:** Ensure `cloudflared` has `depends_on: soc-frontend` with `condition: service_healthy`.

## Immediate Mitigation Steps
1. Restart the tunnel and proxy to clear stale sockets:
   ```bash
   docker compose restart cloudflared soc-frontend
   ```
2. Verify Nginx is reachable locally from the tunnel:
   ```bash
   docker exec -it soc-cloudflared-edge sh
   curl -I http://soc-nginx-proxy:80
   ```
3. Inspect Nginx Error Logs for upstream drops (which indicates the FastAPI backend crashed, rather than the tunnel itself):
   ```bash
   docker logs soc-nginx-proxy | grep error
   ```
